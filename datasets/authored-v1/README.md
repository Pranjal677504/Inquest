# Authored incidents v1

`inquest-authored-v1` contains **16 AI-authored synthetic incidents**, with two cases per supported fault category: one medium and one hard. Each uses the existing eight-service topology and 120-minute telemetry schema. The cases were constructed separately from the procedural incident generator, using explicit keyframes and case-specific logs, events, health, and traces.

This is a public causal stress-test fixture, not an independently validated benchmark or production dataset. “Authored” describes independence from the procedural generator, not an independent human author or external review. Codex prepared these cases for Pranjal Prajapati. Single-author causal and structural checks are recorded; independent domain-expert review is pending. Difficulty labels are design choices, not measured task difficulty.

## Load

```python
from inquest.frozen import load_frozen_set
from inquest.env import InvestigationEnv

cases = load_frozen_set("datasets/authored-v1", "holdout")
assert len(cases) == 16
# Evaluator-side selection; only expose env.call observations to a model.
env = InvestigationEnv(cases[0], max_steps=10)
observation = env.call("get_alerts")
```

Or run `python examples/load_authored_set.py`. Its two queries are predetermined and unscored.

The loader verifies the manifest, data, casebook, and authoring-source checksums; validates scenario records; and binds casebook order and labels to the loaded cases. Authored records explicitly use `origin="authored"`, `split="holdout"`, and `seed=null`. Generated records keep their existing serialization and identity rules. Suite manifest format 2 is explicitly supported alongside smoke manifest format 1.

## Files and audit trail

| File | Purpose |
|---|---|
| `holdout.jsonl` | Canonical labeled evaluation bundles |
| `authoring.json` | Complete case-specific definitions and shared healthy baselines |
| `casebook.json` | Evaluator narratives, expected labels/fixes, distractors, missing-log services, and clue probes |
| [CASEBOOK.md](CASEBOOK.md) | Human-readable causal explanations derived from the checked casebook |
| `manifest.json` | Ordered identities, balance, construction source hashes, freeze date, and limitations |
| `SHA256SUMS` | Checksums for the four canonical JSON/data files |

The renderer in `scripts/build_authored_v1.py` interpolates explicit keyframes and copies supplied records. It has no fault-specific signal dispatch, random sampling, or procedural log-template calls. Shared healthy baselines, schema validation, and the existing fault/fix ontology are reused. The source definitions and generated bytes are committed so every construction choice is inspectable.

To render a review copy into a **new or empty directory**:

```bash
python scripts/build_authored_v1.py --output-dir /tmp/inquest-authored-review
```

The renderer rejects a nonempty output directory. Data and casebook bytes reproduce from the definitions; manifest provenance records the construction revision and code hashes and may differ when rendered from a different checkout. Evaluation should load the frozen bytes, not rebuild them.

From this directory, verify with `sha256sum -c SHA256SUMS` on Linux or `shasum -a 256 -c SHA256SUMS` on macOS. Published data is immutable; any case correction requires a new suite version. Markdown explanation documents may receive clarifications without changing the canonical data.

## What the cases test

- Temporally adjacent but unrelated deploys/configuration changes.
- Missing root-service logs, requiring other telemetry.
- Healthy process liveness despite a failed dependency endpoint.
- TLS rejection before the target application receives a request.
- Shared downstream load whose initiating service differs from the visibly slow service.
- Resource growth under steady arrivals versus genuine demand growth.
- Database plan regression versus migration lock contention.

Each casebook entry contains at least two supporting clue checks and one counterevidence check. These verify clue reachability through the real tools. They do not establish that a model inferred the cause, prove a causal intervention, or substitute for independent review. Gold tool/service relevance remains coarse: some useful caller evidence may receive no credit, and a relevant service match is not claim-level support.

## Evaluation boundary and review status

All bundles, source definitions, explanations, IDs, labels, probes, and the expected reports belong to the evaluator. Agents receive only the budgeted environment's observations. The Python environment is not a sandbox against source access or reflection. Public cases can be memorized; they are not a secret test set.

No agent prompts, model runs, likelihood fitting, or prompt tuning were used to select these cases. Freeze these bytes before a pilot, obtain independent review where possible, and disclose any later tuning against them. Future comparisons should report this suite separately from smoke inputs, count failures in denominators, and retain model/configuration identities and data checksums.

Metrics use flat baselines and piecewise-linear authored changes; logs are sparse. The graph and eight fault classes are fixed, cases contain one labeled initiating fault, and remedial actions are checked against labels rather than executed. No real-world validity, accuracy improvement, calibration, or statistical generalization is claimed.
